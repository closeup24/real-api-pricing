# Стоимость задач AA через квоты подписок

Форк добавляет раздел **«AA + подписки»** в общий ряд бенчмарков Real API Pricing. По горизонтали показана стоимость одной задачи или полного набора AA, по вертикали — Intelligence Index. Используются исходный график Plotly, оформление таблицы, окна подробностей и элементы управления. Все вычисления выполняются при сборке из закреплённых публичных снимков. Для просмотра не нужны ключи API и запросы к платным моделям.

Адрес раздела: `/#board=aa_combined`. Старый `/?view=aa` автоматически открывает этот пункт. Значения цены передаются в график через отдельный адаптер; смена профиля меняет и числа, и единицы оси, подсказок и экспорта. Исходные значения за миллион токенов сохраняются в таблице.

## Расчёт

Для каждой модели и effort используются пять непересекающихся категорий AA: обычный вход, чтение кэша, запись кэша, ответ и reasoning. Токены категории восстанавливаются делением её API-расхода на соответствующую API-ставку. Далее для подписки выбирается один из трёх методов; метод и происхождение данных видны в таблице и фильтрах.

**Квота и ставки:** известны исходные credits/points и ставки их расхода по категориям.

```text
T[j] = API_cost[j] / API_rate_per_million[j] × 1 000 000
U[j] = T[j] × subscription_rate_per_million[j] / 1 000 000
U = сумма U[j]
subscription_cost = monthly_fee × U / monthly_quota
units_per_month = monthly_quota / U
effective_price_per_million = subscription_cost / сумма T[j] × 1 000 000
units_per_100_usd = 100 / subscription_cost
```

Квота и ставки должны быть в одинаковых единицах: например, USD кредитов или points. Для общего и модельного пула берётся меньший доступный объём. Разные модели делят общие пулы: их рассчитанные ёмкости нельзя складывать.

**API-калибровка практического замера:** известны расход сессии в API-эквиваленте и соответствующая доля использованной квоты. При наличии полной разбивки стоимость сессии показана по категориям, без придуманной доли кэша.

```text
P = observed_API_cost / observed_quota_fraction × periods_per_month × plan_multiplier
U = сумма (AA_tokens[j] × API_rate[j] / 1 000 000)
subscription_cost = monthly_fee × U / P
```

Пропорциональность подписочного списания API-стоимости — гипотеза переноса. Один замер сам по себе её не доказывает. Тарифы API должны соответствовать модели и условиям; расходы reasoning не прибавляются повторно к уже включающему их output. Сопутствующие модели, инструменты, округление процентов и перенос между планами перечислены в оговорках.

**Перенос наблюдённого токенного объёма:** если есть практическая оценка ёмкости, но веса списания не восстановлены, сохраняется явно условный сценарий:

```text
subscription_cost = monthly_fee × AA_total_tokens / observed_monthly_tokens
units_per_month = observed_monthly_tokens / AA_total_tokens
```

Он использует токены AA для цены задачи, но не исправляет наблюдённую ёмкость под иной состав нагрузки. Единичные веса категорий в разборе — условие сценария, а не установленные ставки провайдера. Производные оценки и неполные/смешанные замеры включены с отдельным основанием и оговорками. Готовый `monthly_tokens` разрешён только после аудита практического происхождения; величины, рассчитанные через фиксированную смесь RAP, в этот метод не попадают. Фиксированная смесь RAP не используется ни в одном из трёх методов.

Стоимость взвешенной задачи и стоимость полного набора рассчитываются отдельно, по своим компонентам. «Задача AA» — средняя попытка задачи по весам бенчмарков, без деления на балл интеллекта и без гарантии правильного ответа. Подробности весов: [аудит методики](extensions/aa-costs/docs/aa-weighting.md).

## Достоверность

Ставки и исходные квоты восстановлены для 36 сочетаний подписки и модели: GLM Coding, OpenCode Go, Command Code и Ollama. Ещё 28 сочетаний добавлены по практическим источникам: 11 через API-калибровку и 17 через условный перенос наблюдённой ёмкости. Включены обычные подписки OpenAI, Anthropic, Google, SuperGrok, Cursor и Devin в рамках выбранных 13 моделей. Всего доступны 64 пары модель × подписка; SuperGrok Lite для Grok 4.6 исключён из-за отсутствия проверяемого наблюдения. Опубликованные API-стоимости сохранены.

Источники и допущения перечислены для каждого тарифа. При неподтверждённом сопоставлении reasoning с выходом, записи кэша со входом или переносе условий между поколениями тарифов результат отмечается как условный. GLM midpoint — сценарий RAP, а не отдельный официальный тариф. Некоторые квоты ограничены также недельными/короткими окнами. Расчёт за месяц предполагает полное использование квоты; дополнительные расходы инструментов, если они есть, не покрываются пятью токенными категориями AA.

Показатель на $100 нормирует стоимость единицы работы. Он не означает, что любой тариф можно купить ровно за $100. Для реальной подписки отдельно показаны месячная плата и ёмкость.

Сумма восстановленных категорий проверяется по опубликованным счётчикам AA. Найденные расхождения сохраняются, в частности у Fable, и не исправляются скрытым коэффициентом. Исходная стоимость API остаётся исходной. Поэтому эффективная цена миллиона токенов может меняться между effort: меняется состав токенов.

Предыдущий отчёт доступен по `/aa-archive/report.html`. В нём сохранены масштабирование цены по смеси RAP, оценка API и условный перенос наблюдённой токенной ёмкости. Последний не доказывает независимость квоты от состава нагрузки.

## Снимки и воспроизведение

- AA: Intelligence Index 4.3.2, 42 варианта моделей, снимок 22.09.2026; 39 вариантов с обеими стоимостями.
- Тарифы расширения: RAP revision `6489b60a14680a5ce848131d461a90eb054d03ac`.
- Основа интерфейса форка: upstream `b7d9efa1f6ac50a5dfe2f6bfddcab9edf0b36c71`.
- `extensions/aa-costs/data/pricing/quota-rates.json`: исходные квоты, ставки, ссылки и допущения; [описание](extensions/aa-costs/docs/quota-rates.md).
- `extensions/aa-costs/data/pricing/empirical-evidence.json`: практические основания, данные калибровок и три дополнительные пары SuperGrok × Grok 4.7 из upstream `b7d9efa1f6ac50a5dfe2f6bfddcab9edf0b36c71`. Генератор `build_empirical_evidence.mjs` читает закреплённые исследования без сети и сохраняет их SHA-256. [Методика эмпирических оценок](extensions/aa-costs/docs/empirical-estimates.md).
- Аудиты ставок и замеров отдельно привязаны к revision, времени получения и SHA-256 исходных строк тарифов. Несовпадение отключает соответствующую группу оценок до повторной проверки. Новые тарифы добавляются только через явно перечисленные строки эмпирического аудита; исходный снимок не переписывается.

Данные исходной вкладки и расширения имеют разные даты снимков. Новая вкладка показывает свой снимок явно. `npm run data` не обновляет финансовые условия через сеть.

```sh
cd web
npm ci
npm test
npm run build
npm run preview -- --host 127.0.0.1 --port 8765
```

Генератор `web/scripts/build-aa-data.mjs` создаёт JSON новой вкладки и архивный HTML. Расчётные модули и тесты находятся в `extensions/aa-costs/`. Сохранённых JSON достаточно для сборки; исходный большой HTML AA не включён в форк. Для нового получения AA предусмотрен `node scripts/fetch_aa.mjs --refresh` из каталога расширения. Обновление снимков требует новой проверки ставок и квот, а не автоматического переноса старого аудита.

Исходный проект и его лицензия MIT сохранены. Источники данных AA и поставщиков указаны в снимках; лицензия кода не переопределяет условия внешних данных.
