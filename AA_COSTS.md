# Стоимость задач AA через квоты подписок

Форк добавляет раздел **«AA Task Cost»** в общий ряд бенчмарков Real API Pricing. По горизонтали показана стоимость одной задачи или полного набора AA, по вертикали — Intelligence Index. В исходной вкладке AA Intelligence по горизонтали стоит цена миллиона токенов RAP; API и подписки есть в обеих вкладках. Используются исходный график Plotly, оформление таблицы, окна подробностей и элементы управления. Все вычисления выполняются при сборке из закреплённых публичных снимков. Для просмотра не нужны ключи API и запросы к платным моделям.

Адрес раздела: `/#board=aa_combined`. Старый `/?view=aa` автоматически открывает этот пункт. Смена профиля задачи/набора меняет значения и единицы оси, подсказок и экспорта. Обычные вкладки upstream сохраняют собственную методику RAP; описанный здесь расчёт относится только к разделу AA.

## Единый расчёт

Для каждой модели и effort используются пять непересекающихся категорий AA: обычный вход, чтение кэша, запись кэша, ответ и reasoning. Токены категории восстанавливаются делением её API-расхода на соответствующую API-ставку. Затем один и тот же профиль AA умножается на ставки расхода подписочной квоты:

```text
T[j] = AA_API_cost[j] / AA_API_rate_per_million[j] × 1 000 000
U[j] = T[j] × quota_rate_per_million[j] / 1 000 000
U = сумма U[j]
subscription_cost = monthly_fee × U / monthly_quota
units_per_month = monthly_quota / U
effective_price_per_million = subscription_cost / сумма T[j] × 1 000 000
units_per_100_usd = 100 / subscription_cost
```

Это профиль опубликованного расчёта AA. По [методологии AA](https://artificialanalysis.ai/methodology/intelligence-benchmarking), стоимость кэша учитывает измеренную типичную долю попаданий, а не только попадания в одном прогоне. Мы сохраняем этот профиль; он не является замером cache hits внутри каждой подписки.

Квота и ставки должны быть в одинаковых единицах: например, USD кредитов или points. Для общего и модельного пула берётся меньший доступный объём. Разные модели делят общие пулы: их рассчитанные ёмкости нельзя складывать.

Источники весов списания различаются, но формула и профиль токенов общие:

- **Условия тарифа:** исходные credits/points и ставки их расхода по категориям из `quota-rates.json`.
- **API-калибровка практического замера:** известны API-эквивалент расхода и соответствующая доля квоты; при восстановлении стоимости используются измеренные категории. Для переноса на AA принимается гипотеза, что подписочное списание пропорционально API-стоимости.

Во втором случае:

```text
monthly_quota = observed_API_cost / observed_quota_fraction
                × periods_per_month × plan_multiplier
quota_rate[j] = API_rate[j]
```

Доля квоты задаётся числом от 0 до 1: например, 7% = `0.07`. Один замер не доказывает гипотезу API-пропорциональности. Сопутствующие модели, инструменты, округление процентов, тариф записи кэша и перенос между планами перечислены в оговорках.

**Готовый `monthly_tokens` из RAP не участвует в цене задачи.** Перенос общего числа токенов с равными весами категорий отключён. Фиксированная смесь RAP также не используется в разделе AA. Если веса или достаточный исходный замер неизвестны, тариф остаётся в таблице для каждого effort без цены и с причиной; неизвестное значение не становится нулём.

Стоимость взвешенной задачи и стоимость полного набора рассчитываются отдельно, по своим компонентам. «Задача AA» — средняя попытка задачи по весам бенчмарков, без деления на балл интеллекта и без гарантии правильного ответа. Подробности весов: [аудит методики](extensions/aa-costs/docs/aa-weighting.md).

## Покрытие и достоверность

В снимке представлены 65 пар модель × подписка. Для 41 пары есть основание для расчёта: 27 описаний исходных квот и ставок (GLM Coding, OpenCode Go, Command Code, Ollama) и 14 API-калибровок (Luna — 3, Astra — 3, Sol — 3, Devin — 1, Claude Pro — 1, Gemini — 3).

Остальные 24 пары сохраняются без подписочной цены: Claude Max с Opus/Fable — 4, Cursor — 4, SuperGrok с Grok 4.6 — 4 и с Grok 4.7 — 3, старые GLM — 9. Наличие практических данных для этих тарифов не означает, что из них восстановлены веса списания. Например, внутренние доллары Cursor Pro+ не подтверждены как эквивалент API-долларов, а неполный токенный замер не задаёт стоимость отсутствующих категорий. Старые GLM не получают цену: в RAP соединены плата V2 и квоты V3 без подтверждения применимости к старому тарифу.

Итого в данных AA 231 строка: 42 API и 189 подписочных. Цена доступна у 151 строки, включая 112 подписочных; у 77 подписочных строк цены нет из-за неизвестных весов, несовместимых условий квоты или отсутствующих расходов AA. Подробности и арифметика калибровок находятся в [описании практических замеров](extensions/aa-costs/docs/empirical-estimates.md).

Источники и допущения перечислены для каждого тарифа. При неподтверждённом сопоставлении reasoning с выходом, записи кэша со входом или переносе условий результат отмечается как условный. Все API-калибровки условны. GLM midpoint — сценарий RAP, а не отдельный официальный тариф. Некоторые квоты ограничены также недельными/короткими окнами. Расчёт предполагает полное использование доступной квоты; дополнительные расходы инструментов, если они есть, не покрываются пятью токенными категориями AA.

Показатель на $100 нормирует стоимость единицы работы. Он не означает, что любой тариф можно купить ровно за $100. Для подписки отдельно показаны месячная плата и расчётная ёмкость. Недельные замеры нормируются на четыре недели, а не на календарный месяц.

Сумма восстановленных категорий проверяется по опубликованным счётчикам AA. Найденные расхождения сохраняются, в частности у Fable, и не исправляются скрытым коэффициентом. Исходная стоимость API остаётся исходной. Эффективная цена миллиона токенов может меняться между effort: меняется состав токенов.

## Снимки и воспроизведение

- AA: Intelligence Index 4.3.2, 42 варианта моделей, снимок 22.09.2026; 39 вариантов с обеими стоимостями.
- Тарифы расширения: RAP revision `6489b60a14680a5ce848131d461a90eb054d03ac`.
- Основа интерфейса и дополнительные исследования: upstream `b7d9efa1f6ac50a5dfe2f6bfddcab9edf0b36c71`.
- `extensions/aa-costs/data/pricing/quota-rates.json`: исходные квоты, ставки, ссылки и допущения; [описание](extensions/aa-costs/docs/quota-rates.md).
- `extensions/aa-costs/data/pricing/empirical-evidence.json`: данные калибровок, недостающие основания и три дополнительные пары SuperGrok × Grok 4.7. Генератор `build_empirical_evidence.mjs` читает закреплённые исследования без сети и сохраняет их SHA-256.
- Аудиты отдельно привязаны к revision, времени получения и SHA-256 исходных строк тарифов. Несовпадение отключает соответствующие оценки до повторной проверки. Исходный снимок не переписывается при добавлении явно перечисленных тарифов.

Данные обычных вкладок и расширения имеют разные даты снимков. Раздел AA показывает свой снимок явно. `npm run data` не обновляет финансовые условия через сеть.

```sh
cd web
npm ci
npm test
npm run build
npm run preview -- --host 127.0.0.1 --port 8765
```

`web/scripts/build-aa-data.mjs` создаёт только JSON основной вкладки — `web/public/data/aa-costs.json`. `createAaData` не включает `token_scenario`; веб-сборка не строит и не копирует архивный отчёт. Расчётные модули и тесты находятся в `extensions/aa-costs/`. Сохранённых JSON достаточно для сборки; большой исходный HTML AA в форк не включён. Для нового получения AA предусмотрен `node scripts/fetch_aa.mjs --refresh` из каталога расширения. Обновление снимков требует новой проверки ставок и квот.

Исходники прежнего автономного отчёта сохранены для отдельного ручного запуска `node scripts/build_report.mjs` из `extensions/aa-costs/`. Его прежние методы не входят в основной интерфейс и его данные. Подробнее: [README расширения](extensions/aa-costs/README.md).

Исходный проект и его лицензия MIT сохранены. Источники данных AA и поставщиков указаны в снимках; лицензия кода не переопределяет условия внешних данных.
