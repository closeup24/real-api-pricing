# Стоимость задач AA через квоты подписок

Форк добавляет раздел **«AA Task Cost»** в общий ряд бенчмарков Real API Pricing. По горизонтали показана стоимость одной задачи или полного набора AA, по вертикали — Intelligence Index. В исходной вкладке AA Intelligence по горизонтали стоит цена миллиона токенов RAP; API и подписки есть в обеих вкладках. Используются исходный график Plotly, оформление таблицы, окна подробностей и элементы управления. Все вычисления выполняются при сборке из закреплённых публичных снимков. Для просмотра не нужны ключи API и запросы к платным моделям.

Адрес раздела: `/#board=aa_combined`. Старый `/?view=aa` автоматически открывает этот пункт. Смена профиля задачи/набора меняет значения и единицы оси, подсказок и экспорта. Обычные вкладки upstream сохраняют собственную методику RAP; описанный здесь расчёт относится только к разделу AA.

## Единый расчёт

Для каждой модели и effort используются пять непересекающихся категорий AA: обычный вход, чтение кэша, запись кэша, ответ и reasoning. Токены категории восстанавливаются делением её API-расхода на соответствующую API-ставку. Затем один и тот же профиль AA умножается на ставки расхода подписочной квоты:

```text
T[j] = AA_API_cost[j] / AA_API_rate_per_million[j] × 1 000 000
U[j] = T[j] × quota_rate_per_million[j] / 1 000 000
U = сумма U[j]
subscription_cost = monthly_fee × U / monthly_quota
units_per_month = monthly_quota / U
effective_price_per_million = subscription_cost / сумма T[j] × 1 000 000
units_per_100_usd = 100 / subscription_cost
```

Это профиль опубликованного расчёта AA. По [методологии AA](https://artificialanalysis.ai/methodology/intelligence-benchmarking), стоимость кэша учитывает измеренную типичную долю попаданий, а не только попадания в одном прогоне. Мы сохраняем этот профиль; он не является замером cache hits внутри каждой подписки.

Квота и ставки должны быть в одинаковых единицах: например, USD кредитов или points. Для общего и модельного пула берётся меньший доступный объём. Разные модели делят общие пулы: их рассчитанные ёмкости нельзя складывать.

Источники весов списания различаются, но формула и профиль токенов общие:

- **Условия тарифа:** исходные credits/points и ставки их расхода по категориям из `quota-rates.json`.
- **API-калибровка практического замера:** известны API-эквивалент расхода и соответствующая доля квоты; при восстановлении стоимости используются измеренные категории. Для переноса на AA принимается гипотеза, что подписочное списание пропорционально API-стоимости.
- **Приблизительный сценарий по наблюдению:** неполные категории, смешанные модели, сообщённый денежный пул или предполагаемая доля квоты используются с явными поправками и низкой надёжностью. Внутренний доллар может быть условно приравнен к API-доллару; это допущение, а не подтверждённая единица.
- **Перенос между моделями:** условно сохраняется денежный API-эквивалент квоты исходной модели на том же тарифе. Категории AA и ставки берутся у новой модели; такой расчёт не является прямым замером её подписочного расхода.

Для API-калибровки и приблизительного API-сценария:

```text
monthly_quota = observed_API_cost / observed_quota_fraction
                × periods_per_month × plan_multiplier × произведение corrections

или monthly_quota = reported_monthly_pool × plan_multiplier × произведение corrections

quota_rate[j] = API_rate[j] × quota_rate_multiplier
```

Доля квоты задаётся числом от 0 до 1: например, 7% = `0.07`. Сообщённый полный месячный пул не изображается замером расхода 100%. Поправки на акции, модельные ограничения и переносы между планами перечислены отдельно. Множитель ставок по умолчанию равен 1; у Cursor Fast он равен 2, при этом пул и восстановленные токены AA не меняются. Один замер не доказывает гипотезу API-пропорциональности.

Метод `empirical_model_transfer` задаёт `Q[new_model, plan] = Q[source_model, plan]`. Исходный пул восстанавливается по наблюдению и ставкам исходной модели и автоматически следует за изменением этого основания. Пересчитывать старые токены по новым ставкам нельзя. Итоговая надёжность не выше средней и не выше надёжности исходного пула; в интерфейсе все переносы оцениваются по одной рубрике. Применения: Opus 5 → Opus 5.5 на тарифах Claude и GPT-5.6 Sol/Luna → GPT-6 Sol/Luna на соответствующих тарифах ChatGPT. Прямых замеров квот новых моделей нет. [Общий метод и допущения](extensions/aa-costs/docs/empirical-estimates.md#перенос-денежного-пула-между-моделями); историческая сверка лимитов Claude сохранена в [аудите Opus 5.5](extensions/aa-costs/docs/opus55-and-quota-audit.md).

**Готовый `monthly_tokens` из RAP не участвует в цене задачи.** Перенос общего числа токенов с равными весами категорий отключён. Фиксированная смесь RAP также не используется в разделе AA. Неполный замер может дать явно помеченный приблизительный сценарий: отсутствующие категории при этом не объявляются измеренными нулями. Если нет даже пригодного сценарного основания, тариф остаётся в таблице для каждого effort без цены и с причиной; неизвестное значение не становится нулём.

Стоимость взвешенной задачи и стоимость полного набора рассчитываются отдельно, по своим компонентам. «Задача AA» — средняя попытка задачи по весам бенчмарков, без деления на балл интеллекта и без гарантии правильного ответа. Подробности весов: [аудит методики](extensions/aa-costs/docs/aa-weighting.md).

## Покрытие и достоверность

В снимке представлены 74 пары модель × подписка. Для 64 пар есть основание для расчёта: 27 описаний исходных квот и ставок (GLM Coding, OpenCode Go, Command Code, Ollama), 14 API-калибровок (GPT-5.6 Luna — 3, Astra — 3, GPT-5.6 Sol — 3, Devin — 1, Claude Pro — 1, Gemini — 3), 14 приблизительных сценариев (Claude Max — 4, Cursor — 4, SuperGrok 4.6 — 3, SuperGrok 4.7 — 3) и 9 гипотез переноса денежного пула: 3 на Opus 5.5 и по 3 на GPT-6 Sol и Luna, всегда внутри того же тарифа.

Остальные 10 пар сохраняются без подписочной цены: девять старых GLM и SuperGrok Lite. Для GLM в RAP соединены плата V2 и квоты V3 без подтверждения применимости к старому тарифу; у Lite нет проверяемого исходного пула. Это не исправляется предположением о смеси токенов.

Итого в данных AA 299 строк: 59 API и 240 подписочных. Цена доступна у 273 строк: 56 API и 217 подписочных. У 23 подписочных строк цены нет из-за отсутствия допустимого основания или необходимых расходов AA. Подробности и арифметика, включая полный расчёт Fable, находятся в [описании практических замеров](extensions/aa-costs/docs/empirical-estimates.md).

Собственная надёжность раздела AA хранится в `quality`: `high`, `medium`, `low` или `unavailable`, с причинами и ссылками. Среди 74 подписочных пар сейчас 33 имеют среднюю надёжность, 31 — низкую и 10 — без оценки; высокой нет. Это оценка надёжности переноса на AA, отдельная от исходного `confidence` RAP и технического статуса вычисления (`assumed`, `approximate`, `unavailable`). Точная арифметика не превращает условные исходные данные в надёжный прогноз.

У всех пяти категорий метода одна цветовая шкала: приглушённый градиент от красного через жёлтый к зелёному, серый — нет оценки. Снаружи показан только цвет; категория, балл 0–100 и краткое описание раскрываются при наведении, полные основания — в разборе по клику. Это редакционная рубрика качества основания, не вероятность и не процент точности. Например, Fable Max получает 35, Opus 5.5 Pro — 55, Opus 5.5 Max — 25. [Правила шкалы](extensions/aa-costs/docs/empirical-estimates.md#редакционная-шкала-баллов) не меняют стоимость, объёмы задач или расчёт Парето.

Источники и допущения перечислены для каждого тарифа. При неподтверждённом сопоставлении reasoning с выходом, записи кэша со входом или переносе условий результат отмечается как условный. Все API-калибровки условны. GLM midpoint — сценарий RAP, а не отдельный официальный тариф. Некоторые квоты ограничены также недельными/короткими окнами. Расчёт предполагает полное использование доступной квоты; дополнительные расходы инструментов, если они есть, не покрываются пятью токенными категориями AA.

Показатель на $100 нормирует стоимость единицы работы. Он не означает, что любой тариф можно купить ровно за $100. Для подписки отдельно показаны месячная плата и расчётная ёмкость. Недельные замеры нормируются на четыре недели, а не на календарный месяц.

Сумма восстановленных категорий проверяется по опубликованным счётчикам AA. Найденные расхождения сохраняются, в частности у Fable, и не исправляются скрытым коэффициентом. Исходная стоимость API остаётся исходной. Эффективная цена миллиона токенов может меняться между effort: меняется состав токенов.

## Снимки и воспроизведение

- AA: Intelligence Index 4.3.2, 16 моделей и 59 вариантов, снимок 22.09.2026; 56 вариантов с обеими стоимостями. Добавления используют собственные страницы AA: пять effort Opus 5.5 и по шесть у [GPT-6 Sol](https://artificialanalysis.ai/models/gpt-6-sol) и [GPT-6 Luna](https://artificialanalysis.ai/models/gpt-6-luna). Прежние 42 варианта сохранены. Время получения и проверка весов каждого дополнения записаны в `metadata.additions`; прежний аудит `task-weighting.json` не переписан.
- Тарифы расширения: RAP revision `6489b60a14680a5ce848131d461a90eb054d03ac`.
- Основа интерфейса и дополнительные исследования: upstream `b7d9efa1f6ac50a5dfe2f6bfddcab9edf0b36c71`.
- `extensions/aa-costs/data/pricing/quota-rates.json`: исходные квоты, ставки, ссылки и допущения; [описание](extensions/aa-costs/docs/quota-rates.md).
- `extensions/aa-costs/data/pricing/empirical-evidence.json`: данные калибровок, недостающие основания, три дополнительные пары SuperGrok × Grok 4.7 и девять переносов между моделями: Opus 5.5, GPT-6 Sol и GPT-6 Luna. Генератор `build_empirical_evidence.mjs` читает закреплённые исследования без сети и сохраняет их SHA-256.
- Аудиты отдельно привязаны к revision, времени получения и SHA-256 исходных строк тарифов. Несовпадение отключает соответствующие оценки до повторной проверки. Исходный снимок не переписывается при добавлении явно перечисленных тарифов.

Данные обычных вкладок и расширения имеют разные даты снимков. Раздел AA показывает свой снимок явно. `npm run data` не обновляет финансовые условия через сеть.

```sh
cd web
npm ci
npm test
npm run build
npm run preview -- --host 127.0.0.1 --port 8765
```

`web/scripts/build-aa-data.mjs` создаёт только JSON основной вкладки — `web/public/data/aa-costs.json`. `createAaData` не включает `token_scenario`; веб-сборка не строит и не копирует архивный отчёт. Расчётные модули и тесты находятся в `extensions/aa-costs/`. Сохранённых JSON достаточно для сборки; большой исходный HTML AA в форк не включён. Добавление релиза без изменения прежних строк описано в [README расширения](extensions/aa-costs/README.md#сборка-основной-вкладки). Полная замена снимка с дополнениями требует явного `--replace-snapshot` и повторной проверки ставок и квот.

Исходники прежнего автономного отчёта сохранены для отдельного ручного запуска `node scripts/build_report.mjs` из `extensions/aa-costs/`. Его прежние методы не входят в основной интерфейс и его данные. Подробнее: [README расширения](extensions/aa-costs/README.md).

Исходный проект и его лицензия MIT сохранены. Источники данных AA и поставщиков указаны в снимках; лицензия кода не переопределяет условия внешних данных.
