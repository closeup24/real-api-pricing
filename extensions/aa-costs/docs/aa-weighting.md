# Взвешивание стоимости задачи AA

Проверено на снимке от 22 сентября 2026 года, Intelligence Index v4.3.2. Числа и происхождение сохранены в `data/aa/task-weighting.json`; основной снимок не переизвлекался. Таблица Opus включена в шаг 0 вкладки «Расчёт по шагам».

## Что именно усредняется

Пусть `c[m,j]` — средняя долларовая стоимость одной задачи теста `j` у модели `m`, а `w[j]` — вес теста. Тогда:

```text
Cost per Intelligence Index Task[m] = Σ_j w[j] × c[m,j]
```

Сначала определяется цена задачи внутри каждого теста, затем полученные цены усредняются. [Описание графика AA](https://artificialanalysis.ai/#price-and-cost) явно связывает этот показатель с весами тестов в Intelligence Index. Балл конкретной модели не входит в формулу стоимости.

Это дополнительно проверено по встроенным данным AA: для каждого теста сопоставлены `intelligenceIndexEvaluations[].costPerTask` и `intelligenceIndexCostPerTask.evaluations[].weightedCostPerTask`. Их отношение равно весу ниже. Проверены **390 отношений у 39 вариантов моделей**, максимальное отклонение от указанного веса — `2.8e-17`.

| Тест | Задач без повторов | Вес стоимости задачи |
|---|---:|---:|
| AA-Briefcase v1.1 | 91 | 15% |
| GDPval-AA v2.1 | 220 | 10% |

Количество задач и веса также сверены с [таблицей методологии AA](https://artificialanalysis.ai/methodology/intelligence-benchmarking). У AA-Omniscience используются суммарные 15%, а не только 10% компонента accuracy.

Можно понимать взвешенную цену как среднюю цену условной смеси из 100 задач: 15 Briefcase, 10 GDPval, 5 Automation и далее по таблице. Эта смесь задач отличается от состава полного набора. Она также не является смесью токенов cache/input/output.

## Отличие от полной стоимости

Полная стоимость учитывает все задачи тестов без повторных прогонов. При согласованных исходных агрегатах:

```text
Total[m] = Σ_j n[j] × c[m,j]
```

Таким образом, отношение Total между моделями отражает состав полного набора; Cost per Task отражает заданные веса. В полном наборе AA-Omniscience содержит 61.54% всех задач, а Terminal-Bench — 0.677%. Во взвешенной смеси их доли равны 15% и 10%. Дорогие задачи Terminal-Bench сильно влияют на среднюю цену, хотя их мало в полном наборе.

Опубликованное отношение Fable/Opus равно **1.804718** по Total и **1.302354** по взвешенной цене задачи. Это соответственно +80.47% и +30.24%; дополнительной поправки на интеллект модели в расчёте нет.

Для Opus сумма `n[j] × c[m,j]` воспроизводит опубликованный Total `$7274.7418382622345` с машинной точностью. Для Fable она даёт `$13259.517159600253`, тогда как опубликован `$13128.859210511622`: расхождение `$130.657949088631`, или 0.9952%. Причина в открытых данных не установлена; наличие Default Fallback само по себе её не доказывает. Это отдельная несогласованность между агрегатами, не ошибка проверки весов: все десять весов и итоговый Cost per Task у Fable воспроизводятся точно.
