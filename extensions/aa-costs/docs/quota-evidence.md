# Происхождение месячной ёмкости подписок

Аудит относится к 62 строкам подписок в зафиксированном `data/pricing/pricing.json`: RAP `6489b60a14680a5ce848131d461a90eb054d03ac`, получение данных `2026-09-22T10:53:17.553330+00:00`. Цены и квоты не обновлялись. Классификация сохранена в `data/pricing/quota-evidence.json`.

**Официальных абсолютных лимитов в raw tokens в этой выборке не найдено.** Официальные денежные квоты и баллы существуют, но число токенов, полученное делением такой квоты на цену смеси, не становится официальным токенным лимитом. Наблюдаемые месячные значения обычно получены из токенов за часть периода и процента израсходованной квоты. RAP принимает месяц за четыре недели, кроме отдельных месячных пулов.

## Отбор

В условный сценарий переноса наблюдённой ёмкости на нагрузку AA допускаются только `direct_measurement` и `pooled_measurements` с RAP confidence `high` или `medium`, без известных неполных счётчиков и смешанных моделей. Из 62 строк проходят **9**, исключены **53**.

| Метод | Всего | Допущено |
|---|---:|---:|
| `direct_measurement`: конкретный замер, включая пересчёт токены / доля квоты | 9 | 7 |
| `pooled_measurements`: объединение нескольких замеров | 3 | 2 |
| `calibrated_measurement`: замер с поправками на модель или условия | 2 | 0 |
| `plan_extrapolation`: перенос между тарифами или моделями | 11 | 0 |
| `unknown`: основание не установлено | 1 | 0 |
| `synthetic_mix`: денежная квота или баллы, переведённые через смесь RAP | 36 | 0 |

Допуск означает достаточное происхождение **для условного сценария**, а не точный, постоянный или гарантированный лимит. Классификация проверяет сохранённые источники и примечания RAP; пользовательские замеры независимо не повторялись. Отсутствие известного дефекта в примечаниях не доказывает полноту всей исходной телеметрии.

### Почему исключены остальные наблюдательные основы

- Astra Plus: output отсутствует в использованном счётчике. Ссылка RAP на малую долю выхода Luna не восстанавливает выход Astra.
- Sol Pro 20x: в объединённое значение включены сегменты с Astra; их вес снижен, но они не удалены.
- Claude Pro / Opus 5: total включает около 23 тысяч токенов Haiku. Доля мала, но строгий критерий одной модели не выполнен.
- Claude Max 20x / Opus 5: смешанный замер пересчитан с поправками на акцию и последующие условия. Более поздний чистый образец служит лишь дополнительным подтверждением.
- Claude Max 20x / Fable 5.1: месячная ёмкость выведена через восстановленный вес Fable относительно Opus и ограничение 50% недельной квоты; у исходной части Opus не перечислены отдельно input и cache write.

Одиннадцать экстраполяций не становятся независимыми измерениями даже при официальном коэффициенте тарифа. SuperGrok Lite исключён из-за неясной основы. Все 36 `synthetic_mix` исключены независимо от confidence: GLM Coding — 18 строк, OpenCode — 5, Command Code — 7, Ollama — 6.

## Перенос на смесь AA

**Ни для одной строки перенос raw-token ёмкости между смесями не подтверждён.** Поэтому у всех записей `cross_mix_transfer_confirmed=false`. При принятии такой ёмкости за условную константу можно разделить её на токены задачи AA, но результат описывает именно это допущение. Он не доказывает, что реальная подписка выполнит столько задач.

Для Gemini имеется более сильное ограничение: внутри наблюдения отношение расходов квоты около 0.405 совпадает с отношением стоимости около 0.407 лучше, чем с отношением raw tokens 0.448. Сам RAP поясняет, что raw-token ёмкость меняется со смесью. У Cursor также указан учёт по стоимости; различие Standard/Fast нельзя свести к обязательному отношению raw-token ёмкостей 2:1. Эти строки оставлены только для явно условного сценария и снабжены отдельными `mix_transfer_status` и примечаниями.

Изменение effort, длины контекста, доли кэша, режима обслуживания, аккаунта или условий тарифа также может изменить фактическую ёмкость. Среднемесячная арифметика предполагает возможность использовать соответствующие недельные и короткие окна квоты; она не гарантирует их полное использование.

## Поля и контроль снимка

Ключ строки `id` точно совпадает с `pricing.rows[].id`; metered API в manifest не входят. `token_limit_kind=observed_workload` обозначает происхождение из наблюдаемой нагрузки, включая исключённые производные оценки. Для `synthetic_mix` и `unknown` значение равно `null`. Решение об использовании принимается по `usable_for_observed_scenario`, а не по одному `token_limit_kind`.

`observed_mix` задана только для Luna Plus, Devin Max / Astra и Gemini AI Pro. Для Devin все четыре доли получены из точных опубликованных счётчиков. Для Luna доли округлены. Для Gemini доли нормированы по сумме округлённых компонентов 55.344 млн, которая на 0.001 млн отличается от приведённого total 55.343 млн; принятая месячная ёмкость при этом не меняется. У Luna и Gemini `cache_write_share=null`: отдельный счётчик не сообщён. `null` не следует заменять нулём. Смесь базового замера не записана как наблюдённая смесь производного тарифа.

Перед применением manifest следует проверить `metadata.pricing_revision`, `metadata.pricing_retrieved_at_utc` и `metadata.pricing_rows_sha256`. Последний равен SHA-256 UTF-8 строки `JSON.stringify(pricing.rows)` **для всего массива, включая API**. При несовпадении сценарий следует отключить до повторного аудита, а не автоматически наследовать допуски по похожим названиям.
