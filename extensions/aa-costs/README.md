# Стоимость задач LLM по API и подпискам

Расширение встроено в [форк Real API Pricing](https://github.com/closeup24/real-api-pricing). Основной интерфейс запускается из `web/` и содержит пункт **«AA Task Cost»** в общем переключателе бенчмарков: `/#board=aa_combined`. Подробное описание: [AA_COSTS.md](../../AA_COSTS.md).

## Основной расчёт

Для каждой модели и effort берутся пять категорий AA: обычный вход, чтение кэша, запись кэша, ответ и reasoning. Их объёмы восстанавливаются из расходов и API-ставок AA и умножаются на ставки списания квоты подписки.

```text
T[j] = AA_cost[j] / AA_API_rate_per_million[j] × 1 000 000
quota_used = сумма (T[j] × quota_rate_per_million[j] / 1 000 000)
subscription_cost = monthly_fee × quota_used / monthly_quota
units_per_month = monthly_quota / quota_used
units_per_100_usd = 100 / subscription_cost
```

Используется один профиль AA и одна формула. Основания для ставок — исходные credits/points с ценами категорий, условная API-калибровка практического замера, приблизительный сценарий по неполному наблюдению либо явно отмеченный перенос денежного пула между моделями:

```text
monthly_quota = observed_API_cost / observed_quota_fraction
                × periods_per_month × plan_multiplier × произведение corrections
или monthly_quota = reported_monthly_pool × plan_multiplier × произведение corrections
quota_rate[j] = API_rate[j] × quota_rate_multiplier
```

Калибровка предполагает API-пропорциональность подписочного списания. Она не устанавливает внутренние правила провайдера. В приблизительных сценариях неполные категории, предполагаемые проценты и соответствие внутренних долларов API-долларам отмечены как допущения низкой надёжности. Сообщённый полный пул не выдаётся за измеренный расход 100%. Источники, смешанные вызовы, промопоправки и переносы между планами указаны в [описании замеров](docs/empirical-estimates.md). Недельные измерения нормируются на четыре недели, а не на календарный месяц. Общие пулы моделей одной подписки нельзя складывать.

Метод `empirical_model_transfer` условно переносит денежный API-эквивалент квоты исходной модели на новую только внутри того же тарифа. Расходы задачи восстанавливаются по собственным данным AA и ставкам новой модели. Старый замер не переоценивается по новым ставкам и не превращается в токенный лимит. Общая надёжность не выше средней и ограничена надёжностью источника. Прямых замеров новых моделей нет. Этот единый метод применяется к Opus 5 → Opus 5.5 и GPT-5.6 Sol/Luna → GPT-6 Sol/Luna; [формулы и допущения](docs/empirical-estimates.md#перенос-денежного-пула-между-моделями), [исторический аудит Opus](docs/opus55-and-quota-audit.md).

Все пять категорий метода используют общий приглушённый градиент оценки 0–100; отсутствие оценки показано серым. Снаружи остаётся только цвет, а категория, балл и краткое описание открываются при наведении, полные основания — в разборе по клику. Шкала редакционная, не вероятность или процент точности; она не меняет цены и Парето. Правила и примеры собраны в [одной рубрике](docs/empirical-estimates.md#редакционная-шкала-баллов).

**Общая ёмкость `monthly_tokens` и фиксированная смесь RAP не входят в цену задачи раздела AA.** Перенос токенного объёма с равными весами отключён. Неполные наблюдения допускаются как явно помеченные сценарии; их неизвестные категории не объявляются измеренными нулями. При отсутствии даже сценарного основания тариф остаётся в таблице для каждого effort без цены и с причиной. Обычные вкладки upstream сохраняют методику RAP.

Стоимость взвешенной задачи и полного набора AA считается отдельно. `cost_per_task` — взвешенная средняя стоимость попытки, а не цена гарантированного правильного ответа; балл интеллекта не входит в знаменатель. Веса одинаковы для моделей: Briefcase и Omniscience по 15%, Automation и LCR по 5%, остальные шесть тестов по 10%. Проверка опубликованных значений: [методика AA](docs/aa-weighting.md).

Cache write использует полную ставку записи, а не надбавку к input. Reasoning не суммируется повторно с включающим его output. Сопоставления неизвестных ставок отмечаются как допущения. Для подписочного расчёта полного набора также используется сумма восстановленных категорий; опубликованный общий счётчик служит отдельной сверкой. Расхождения, в частности у пяти вариантов Fable, сохраняются с пометкой приблизительности.

Средняя цена миллиона токенов может меняться между effort, поскольку меняется состав нагрузки. «Задач на $100» — нормировка стоимости; она не означает возможность купить часть месячной подписки. Расчёт предполагает полное использование квоты одной моделью и выбранным effort, а краткосрочные ограничения могут уменьшить доступный объём.

## Покрытие снимка

- 16 моделей и 59 вариантов AA; исходные расходы есть у 56 вариантов. Новые модели используют собственные данные AA: пять effort Opus 5.5 и по шесть у GPT-6 Sol и Luna.
- Из 74 пар модель × подписка основание для расчёта есть у 64: 27 с совместимыми исходными квотами и ставками, 14 с API-калибровкой, 14 с приблизительным сценарием и 9 с переносом денежного пула между моделями — 3 для Opus 5.5 и по 3 для GPT-6 Sol и Luna.
- 10 пар без достаточного основания: 9 GLM old и SuperGrok Lite. Их строки сохранены для всех effort без подписочной цены.
- Файл исходных ставок сохраняет 36 записей: 27 `assumed` и 9 `unavailable`. У отдельных доступных тарифов цена effort также отсутствует, если AA не опубликовал необходимые расходы.
- Всего 299 строк: 59 API и 240 подписочных. У 273 строк есть цена: 56 API и 217 подписочных; 23 подписочные строки без цены.
- Надёжность подписочных пар в собственной шкале AA: 33 `medium`, 31 `low`, 10 `unavailable`; `high` пока нет. Поле `quality` с причинами и ссылками отдельно от `confidence` RAP и статуса арифметики.

API-калибровки покрывают ChatGPT GPT-5.6 Luna / Astra / GPT-5.6 Sol по три тарифа, Devin Max + Astra, Claude Pro + Opus и три Google-подписки с Gemini. GPT-5.6 Sol использует четыре сегмента gateway Pro 20x, а меньшие планы получены явной экстраполяцией. Новые GPT-6 используют отдельные гипотезы переноса этих пулов; их собственных подписочных замеров нет. Devin использует измеренные категории с допущением о ставке cacheCreate. Подробности: [эмпирические оценки](docs/empirical-estimates.md), [квоты и ставки](docs/quota-rates.md).

Приблизительные сценарии покрывают Claude Max с Opus/Fable (4 пары), Cursor (4), SuperGrok с Grok 4.6 (3) и Grok 4.7 (3). Все 14 имеют низкую надёжность. У Cursor Fast ставки удвоены после восстановления токенов AA; общий пул не уменьшается второй раз. В сценарии Fable весь смешанный образец условно оценивается как Fable, с отдельно показанными промопоправками и модельным лимитом; это не чистое измерение Fable.

Для Opus 5 × Max используется полный сообщённый расход `$1222` за 52% недели: `$9400` за четыре недели на Max 20x и условная половина `$4700` на Max 5x. Прежний расход `$1050` был неполным и учитывал только чтение кэша. [Автор замера](https://www.reddit.com/r/ClaudeCode/comments/1wk3zq5/comment/panzsk1/) сообщает преимущественно Opus 4.6 и Fable 5.1, а не Opus 5: это сценарий переноса общего пула, с оценкой 25/100; следующий перенос на Opus 5.5 получает 15/100. Pro остаётся 65/100 и 55/100 соответственно. [Полный аудит и условное сравнение Pro/Max](docs/opus55-and-quota-audit.md#почему-pro-пока-получается-дешевле).

У девяти GLM old исходный RAP соединяет плату V2 с квотой V3. Совместимость поколений не подтверждена, поэтому эти строки не рассчитываются. Девять GLM new используют условия V3; три варианта mid остаются условными временными сценариями. Фиксированная смесь токенов RAP в расчёте AA не применяется.

Снимок AA — Intelligence Index 4.3.2 от 22.09.2026. Дополнения Opus 5.5, [GPT-6 Sol](https://artificialanalysis.ai/models/gpt-6-sol) и [GPT-6 Luna](https://artificialanalysis.ai/models/gpt-6-luna) используют их собственные страницы. Исходные 42 строки и прежний аудит весов сохранены. В `metadata.additions` записаны даты, fingerprints и отдельная проверка весов и стоимостей каждого дополнения. Базовые тарифы закреплены на RAP `6489b60a14680a5ce848131d461a90eb054d03ac`, дополнительные исследования — на `b7d9efa1f6ac50a5dfe2f6bfddcab9edf0b36c71`. Аудиты связаны с revision, временем получения и SHA-256 строк тарифов; после смены снимка их требуется перепроверить.

## Сборка основной вкладки

Из корня форка:

```sh
cd web
npm ci
npm test
npm run build
npm run preview -- --host 127.0.0.1 --port 8765
```

Сборка читает сохранённые JSON без сети. `web/scripts/build-aa-data.mjs` формирует `web/public/data/aa-costs.json`. Функция `createAaData` содержит единый `quota_scenario`, разбивку `api_estimate` и проверенные веса тестов; `token_scenario` в основной результат не входит. Архивный HTML не строится и не копируется в веб-интерфейс.

Расчётные проверки отдельно, из каталога расширения:

```sh
node --test tests/*.test.mjs
node scripts/build_empirical_evidence.mjs
```

Добавление новых релизов без изменения прежних строк, из каталога расширения:

```sh
node scripts/fetch_aa.mjs --add-release claude-opus-5-5 --model-id claude-opus-5.5 --refresh
node scripts/fetch_aa.mjs --add-release gpt-6-sol --model-id gpt-6-sol --refresh
node scripts/fetch_aa.mjs --add-release gpt-6-luna --model-id gpt-6-luna --refresh
```

`--refresh` получает HTML через сеть; без него используется локально сохранённый HTML. Если релиз уже добавлен, команда завершится без изменения среза. Исходные объекты каждого дополнения записаны отдельно в `data/aa/<release-slug>-raw.json`. Полная замена среза с дополнениями требует явного `node scripts/fetch_aa.mjs --refresh --replace-snapshot`; это не обновление отдельных новых строк. Цены RAP обновляются отдельно через `scripts/fetch_pricing.py --refresh`. Финансовые условия не обновляются обычной сборкой. Новые данные требуют повторной проверки сопоставлений и аудитов.

## Файлы

- `data/aa/aa.json` — модели, effort, расходы, индекс, API-ставки и счётчики AA.
- `data/aa/task-weighting.json` — проверенные веса тестов и денежные вклады.
- `data/aa/*-raw.json` — отдельные исходные объекты дополнений Opus 5.5, GPT-6 Sol и GPT-6 Luna; их проверки весов хранятся в `aa.json` → `metadata.additions`.
- `data/pricing/pricing.json` — закреплённые тарифы и справочные значения RAP.
- `data/pricing/quota-rates.json` — исходные квоты, ставки категорий и оговорки.
- `data/pricing/empirical-evidence.json` — API-калибровки, сценарии, переносы между моделями, недостающие основания и ссылки.
- `data/pricing/claude-max-source-review.json` — первоисточник полного расхода Max, состав моделей и ограничения сравнения с Pro.
- `data/pricing/quota-evidence.json` — аудит происхождения прежних ёмкостей; сам объём токенов не задаёт цену в основной вкладке.
- `scripts/estimate_api_price.mjs` — восстановление категорий AA и сверки счётчиков.
- `scripts/quota_scenario.mjs` — расчёт по категориям AA и ставкам квоты.
- `scripts/empirical_scenario.mjs` — калибровки, переносы денежного пула и сохранение строк без достаточных весов.
- `scripts/build_empirical_evidence.mjs` — воспроизводимый аудит закреплённых исследований.
- `tests/` — проверки расчётов и целостности данных.

## Архив прежних расчётов

Исходники автономного отчёта сохранены для изучения предыдущих подходов: масштабирования цены через смесь RAP и переноса наблюдённой общей токенной ёмкости. Эти подходы не входят в основной раздел AA. Старый `scripts/token_scenario.mjs` также сохранён только для архива.

Архив можно построить отдельной командой из этого каталога:

```sh
node scripts/build_report.mjs
```

Результат записывается в `output/report.html` и сопутствующие файлы. Для отдельного локального просмотра предусмотрен `node scripts/preview.mjs`. Обычная веб-сборка не вызывает этот генератор и не публикует `/aa-archive/report.html`.
