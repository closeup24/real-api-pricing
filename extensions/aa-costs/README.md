# Стоимость задач LLM по API и подпискам

Расширение встроено в [форк Real API Pricing](https://github.com/closeup24/real-api-pricing). Основной интерфейс запускается из `web/` и содержит пункт **«AA Task Cost»** в общем переключателе бенчмарков: `/#board=aa_combined`. Подробное описание: [AA_COSTS.md](../../AA_COSTS.md).

## Основной расчёт

Для каждой модели и effort берутся пять категорий AA: обычный вход, чтение кэша, запись кэша, ответ и reasoning. Их объёмы восстанавливаются из расходов и API-ставок AA и умножаются на ставки списания квоты подписки.

```text
T[j] = AA_cost[j] / AA_API_rate_per_million[j] × 1 000 000
quota_used = сумма (T[j] × quota_rate_per_million[j] / 1 000 000)
subscription_cost = monthly_fee × quota_used / monthly_quota
units_per_month = monthly_quota / quota_used
units_per_100_usd = 100 / subscription_cost
```

Используется один профиль AA и одна формула. Основания для ставок — исходные credits/points с ценами категорий либо условная API-калибровка практического замера:

```text
monthly_quota = observed_API_cost / observed_quota_fraction
                × periods_per_month × plan_multiplier
quota_rate[j] = API_rate[j]
```

Калибровка предполагает API-пропорциональность подписочного списания. Она не устанавливает внутренние правила провайдера. Источники, смешанные вызовы, ставки записи кэша, округление процентов и переносы между планами указаны в [описании замеров](docs/empirical-estimates.md). Недельные измерения нормируются на четыре недели, а не на календарный месяц. Общие пулы моделей одной подписки нельзя складывать.

**Общая ёмкость `monthly_tokens` и фиксированная смесь RAP не входят в цену задачи раздела AA.** Перенос токенного объёма с равными весами отключён. При неизвестных весах или неполном исходном замере тариф остаётся в таблице для каждого effort без цены и с причиной. Отсутствующие значения не подменяются нулями. Обычные вкладки upstream сохраняют методику RAP.

Стоимость взвешенной задачи и полного набора AA считается отдельно. `cost_per_task` — взвешенная средняя стоимость попытки, а не цена гарантированного правильного ответа; балл интеллекта не входит в знаменатель. Веса одинаковы для моделей: Briefcase и Omniscience по 15%, Automation и LCR по 5%, остальные шесть тестов по 10%. Проверка опубликованных значений: [методика AA](docs/aa-weighting.md).

Cache write использует полную ставку записи, а не надбавку к input. Reasoning не суммируется повторно с включающим его output. Сопоставления неизвестных ставок отмечаются как допущения. Для подписочного расчёта полного набора также используется сумма восстановленных категорий; опубликованный общий счётчик служит отдельной сверкой. Расхождения, в частности у пяти вариантов Fable, сохраняются с пометкой приблизительности.

Средняя цена миллиона токенов может меняться между effort, поскольку меняется состав нагрузки. «Задач на $100» — нормировка стоимости; она не означает возможность купить часть месячной подписки. Расчёт предполагает полное использование квоты одной моделью и выбранным effort, а краткосрочные ограничения могут уменьшить доступный объём.

## Покрытие снимка

- 13 моделей и 42 варианта AA; исходные расходы есть у 39 вариантов.
- Из 65 пар модель × подписка основание для расчёта есть у 41: 27 с совместимыми исходными квотами и ставками и 14 с API-калибровкой.
- 24 пары без достаточного основания: 9 GLM old, 4 Claude Max, 4 Cursor и 7 SuperGrok. Их строки сохранены для всех effort без подписочной цены.
- Файл исходных ставок сохраняет 36 записей: 27 `assumed` и 9 `unavailable`. У отдельных доступных тарифов цена effort также отсутствует, если AA не опубликовал необходимые расходы.
- Всего 231 строка: 42 API и 189 подписочных. У 151 строки есть цена; среди подписочных 112 с ценой и 77 без неё.

API-калибровки покрывают ChatGPT Luna/Astra/Sol по три тарифа, Devin Max + Astra, Claude Pro + Opus и три Google-подписки с Gemini. Sol использует четыре сегмента gateway Pro 20x, а меньшие планы получены явной экстраполяцией. Devin использует измеренные категории с допущением о ставке cacheCreate. Подробности: [эмпирические оценки](docs/empirical-estimates.md), [квоты и ставки](docs/quota-rates.md).

У девяти GLM old исходный RAP соединяет плату V2 с квотой V3. Совместимость поколений не подтверждена, поэтому эти строки не рассчитываются. Девять GLM new используют условия V3; три варианта mid остаются условными временными сценариями. Фиксированная смесь токенов RAP в расчёте AA не применяется.

Снимок AA — Intelligence Index 4.3.2 от 22.09.2026. Базовые тарифы закреплены на RAP `6489b60a14680a5ce848131d461a90eb054d03ac`, дополнительные исследования — на `b7d9efa1f6ac50a5dfe2f6bfddcab9edf0b36c71`. Аудиты связаны с revision, временем получения и SHA-256 строк тарифов; после смены снимка их требуется перепроверить.

## Сборка основной вкладки

Из корня форка:

```sh
cd web
npm ci
npm test
npm run build
npm run preview -- --host 127.0.0.1 --port 8765
```

Сборка читает сохранённые JSON без сети. `web/scripts/build-aa-data.mjs` формирует `web/public/data/aa-costs.json`. Функция `createAaData` содержит единый `quota_scenario`, разбивку `api_estimate` и проверенные веса тестов; `token_scenario` в основной результат не входит. Архивный HTML не строится и не копируется в веб-интерфейс.

Расчётные проверки отдельно, из каталога расширения:

```sh
node --test tests/*.test.mjs
node scripts/build_empirical_evidence.mjs
```

Обновление источников выполняется отдельно через `scripts/fetch_aa.mjs --refresh` и `scripts/fetch_pricing.py --refresh`. Для загрузки нужны соответствующие сетевые инструменты; финансовые условия не обновляются обычной сборкой. Новые данные требуют повторной проверки сопоставлений и аудитов.

## Файлы

- `data/aa/aa.json` — модели, effort, расходы, индекс, API-ставки и счётчики AA.
- `data/aa/task-weighting.json` — проверенные веса тестов и денежные вклады.
- `data/pricing/pricing.json` — закреплённые тарифы и справочные значения RAP.
- `data/pricing/quota-rates.json` — исходные квоты, ставки категорий и оговорки.
- `data/pricing/empirical-evidence.json` — API-калибровки, недостающие основания и ссылки.
- `data/pricing/quota-evidence.json` — аудит происхождения прежних ёмкостей; сам объём токенов не задаёт цену в основной вкладке.
- `scripts/estimate_api_price.mjs` — восстановление категорий AA и сверки счётчиков.
- `scripts/quota_scenario.mjs` — расчёт по категориям AA и ставкам квоты.
- `scripts/empirical_scenario.mjs` — калибровки и сохранение строк без достаточных весов.
- `scripts/build_empirical_evidence.mjs` — воспроизводимый аудит закреплённых исследований.
- `tests/` — проверки расчётов и целостности данных.

## Архив прежних расчётов

Исходники автономного отчёта сохранены для изучения предыдущих подходов: масштабирования цены через смесь RAP и переноса наблюдённой общей токенной ёмкости. Эти подходы не входят в основной раздел AA. Старый `scripts/token_scenario.mjs` также сохранён только для архива.

Архив можно построить отдельной командой из этого каталога:

```sh
node scripts/build_report.mjs
```

Результат записывается в `output/report.html` и сопутствующие файлы. Для отдельного локального просмотра предусмотрен `node scripts/preview.mjs`. Обычная веб-сборка не вызывает этот генератор и не публикует `/aa-archive/report.html`.
