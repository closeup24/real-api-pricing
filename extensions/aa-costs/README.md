# Стоимость задач LLM по API и подпискам

Расширение встроено в [форк Real API Pricing](https://github.com/closeup24/real-api-pricing). Основной интерфейс запускается из `web/` репозитория и содержит пункт «AA + подписки» в общем переключателе бенчмарков. Он считает стоимость по исходным кредитам/баллам подписки и пяти категориям токенов AA, без фиксированной смеси RAP. Описание: [AA_COSTS.md](../../AA_COSTS.md), [источники ставок](docs/quota-rates.md).

Ниже описан сохранённый автономный отчёт предыдущих методов. Он по-прежнему строится командой `node scripts/build_report.mjs` и доступен в интерфейсе по `/aa-archive/report.html`. Та же сборка записывает новый `output/quota-scenario.json`; нативный интерфейс читает данные, подготовленные `web/scripts/build-aa-data.mjs`.

Проект объединяет стоимость задач Artificial Analysis с эффективными ценами тарифов Real API Pricing. Для каждой найденной модели сохраняются опубликованные варианты effort и добавляются доступные тарифы.

Результат — автономный интерактивный отчёт `output/report.html`: два графика, фильтры, таблица исходных и пересчитанных цен, выгрузка выбранных строк. Файл открывается в браузере без сервера и подключения к интернету.

Основные фильтры поддерживают множественный выбор моделей, разработчиков, каналов доступа, тарифов, оплаты, effort и уверенности оценки квоты. Внутри группы действует ИЛИ, между группами — И. Диапазоны месячной платы ограничивают подписки; API остаются, если выбран этот способ оплаты. Графики, таблица и CSV используют один отбор. Уверенность квоты не применима к API. Канал доступа обозначает продукт (например, Cursor), а разработчик — создателя модели (например, Anthropic).

Вкладка **«Расчёт по шагам»** (`#calculation`) показывает весь метод на Claude Opus 5 max и Claude Max 20x: деление расходов на ставки, суммы токенов, две средние API-цены, сверки, фиксированную смесь RAP, цену подписки, коэффициент и задачи на $100. Все операции содержат числа из текущего снимка; переключатель показывает сохранённую точность. Пример не зависит от фильтров вкладки сравнения.

Вкладка **«По токенам AA»** (`#token-scenario`) рассчитывает другой сценарий: наблюдённая месячная ёмкость подписки делится на токены задачи AA для конкретного effort. Фиксированная смесь RAP и его готовая API-цена в этом методе не используются. Происхождение каждой квоты проверено отдельно; исключённые тарифы показаны с причинами.

## Расчёт

Для модели `m` и тарифа `p`:

```text
multiplier(m, p) = real_price(m, p) / api_price(m)
task_cost(m, effort, p) = aa_task_cost(m, effort) × multiplier(m, p)
total_cost(m, effort, p) = aa_total_cost(m, effort) × multiplier(m, p)
tasks_on_budget = budget / task_cost
```

Обе цены токенов выражены в USD за миллион. API-стоимости AA сохраняются как исходные строки с коэффициентом 1. Подписки получают тот же Intelligence Index, что и соответствующий вариант модели и effort в AA.

В отчёте доступны две API-базы: **Artificial Analysis** по умолчанию и **Real API Pricing**. Первая согласует знаменатель со ставками исходного бенчмарка; вторая буквально воспроизводит отношение цен RAP. Обе используют одну смесь токенов. На снимке 22.09.2026 базы совпадают у 11 моделей. У MiMo V2.5 Pro база RAP равна $0,227/MTok, AA — $0,0159075/MTok; у GLM 5.3 Flash — $0,034225 и $0,030325 соответственно. Поэтому исходный коэффициент RAP нельзя без оговорки считать скидкой от текущего API AA. Данные обоих сценариев сохранены.

`cost_per_task` — взвешенная средняя стоимость попытки задачи по методике AA. `cost_total` — стоимость полного набора AA без повторных прогонов. Это разные способы усреднения нагрузки; балл интеллекта в их знаменатель не входит.

Стоимость задачи вычисляется как `Σ вес_теста × средняя_цена_задачи_теста`. Веса одинаковы для моделей: Briefcase и Omniscience по 15%, Automation и LCR по 5%, остальные шесть тестов по 10%. Эти веса подтверждены 390 отношениями опубликованных стоимостей у 39 вариантов. Подробная таблица, пример Opus/Fable и обнаруженная несогласованность полного итога Fable находятся в [docs/aa-weighting.md](docs/aa-weighting.md).

## Средняя API-цена по данным AA

Отдельный раздел отчёта рассчитывает USD за миллион **всех** токенов для каждой модели и effort, используя только расходы, ставки и счётчики AA. Сравнение с RAP показано рядом, но не участвует в восстановлении токенов.

Три колонки состава токенов показывают доли чтения кэша, входа с записью кэша и выхода. Вход разбит на обычный input и cache write, выход включает answer и reasoning. Знаменатель — сумма восстановленных токенов выбранного профиля: задачи или полного набора. Три доли дают 100% до округления. Приближённая разбивка Fable отмечена знаком «≈», даже когда цена полного набора рассчитана напрямую. CSV хранит доли от 0 до 1 для обоих профилей.

Колонка «API-база из RAP» показывает только независимую базу RAP; для дополненных из AA значений указано «Нет в RAP». Например, $1,365/MTok для Astra получены из ставок AA: `0,975 × 1 + 0,0215 × 10 + 0,0035 × 50 = 1,365`. Это фиксированная смесь RAP со ставками AA, а не найденная цена Astra в RAP. В основной таблице расчёт раскрывается под API-ценой.

Для взвешенной задачи используются пять непересекающихся категорий: обычный input, cache read, cache write, answer и reasoning:

```text
tokens(category) = cost(category) / rate_per_million(category) × 1 000 000
aa_task_api_price = task_cost / sum(tokens(category)) × 1 000 000
aa_suite_api_price = suite_cost / (published_input_tokens + published_output_tokens) × 1 000 000
```

Для полного набора AA публикует общее количество токенов, поэтому его основная цена вычисляется напрямую. Обратный расчёт категорий используется для проверки. Для задачи полного input-счётчика нет; сверяются опубликованные output, answer и reasoning. Агрегаты input/output не добавляются повторно к сумме их категорий.

Cache write использует полную ставку записи, а не надбавку к input. Когда отдельной ставки записи нет, принимается input-ставка с явной пометкой предположения. Reasoning рассчитывается по output-ставке: отдельного тарифа источник не публикует. При неизвестной или нулевой ставке обратный расчёт не выдаёт выдуманное число токенов.

В снимке 22.09.2026 цена доступна для 39 из 42 вариантов. У 34 восстановленные токены совпадают с опубликованными счётчиками с численным допуском 0,000001%. У пяти вариантов Fable с пометкой Default Fallback есть расхождения; причина не установлена. Их инверсия отмечена как приблизительная. Основная цена полного набора по опубликованным токенам не зависит от этой инверсии.

**Одинаковая средняя цена между effort не является условием правильности.** Отдельные тарифы могут быть постоянными, но доли кеша и output меняются. Например, цена взвешенной задачи Astra лежит в диапазоне $2,849–3,602/MTok, Opus 5 — $0,897–1,194/MTok, Luna — $0,035–0,138/MTok. Эти средние также не обязаны совпадать с RAP: тот использует фиксированную смесь 97,5/2,15/0,35%, а здесь восстановлена смесь конкретной нагрузки AA. Базы, ранее дополненные из AA, явно обозначены и не считаются независимым сравнением с RAP.

Новая оценка позволяет получить эффективную API-цену нагрузки AA без готовой строки RAP. Она не заменяет знаменатель исходного пересчёта подписок автоматически: эффективная цена подписки в RAP и цена AA относятся к разным смесям токенов. Для прямого переноса новой средней на подписку требуется предположение, что её квота расходуется одинаково на все категории токенов. Само совпадение обратного расчёта такого предположения не подтверждает.

## Сценарий по наблюдённой ёмкости и токенам AA

Из RAP берутся только месячная плата, оценка месячного объёма токенов и доказательства её происхождения. Включаются прямые или объединённые наблюдения конкретной пары модель + тариф с уверенностью high/medium и достаточным учётом токенов. Объёмы, выведенные из заранее заданной смеси, переносы между тарифами, смешанные модели, неполные счётчики и слабые источники исключаются. Подробности находятся в [аудите квот](docs/quota-evidence.md).

Для месячной платы `F`, наблюдённой месячной ёмкости `Q` и токенов профиля AA `T`:

```text
subscription_price_per_million = F / Q × 1 000 000
aa_api_price_per_million = AA_cost / T × 1 000 000
subscription_cost = F × T / Q
tasks_per_month = Q / T_task
tasks_per_100_usd = 100 / subscription_task_cost
```

Для задачи `T` восстанавливается по пяти категориям расходов AA; для полного набора используется опубликованное число input + output. Смеси задачи и набора различаются и сохраняются отдельно. Цена токена подписки при условно фиксированной `Q` одинакова для всех effort; меняются токены на задачу и количество задач. Эквивалентный множитель `subscription_price / aa_api_price` также различается по effort и профилю задачи/набора.

**Это условие расчёта, а не установленное свойство квоты.** В отобранных источниках месячная ёмкость получена из наблюдений при своей нагрузке. Официальных фиксированных лимитов общего числа токенов и подтверждённого переноса между смесями в этой выборке нет. Например, расход квоты Google зависит от API-стоимости токенов. Надёжный исходный замер не доказывает, что тот же объём доступен при другой доле кэша, ином effort или другом режиме продукта. В интерфейсе и выгрузке эта неопределённость явно сохранена; никакой произвольной поправки на неё нет.

Аудит связан с revision, временем получения и SHA-256 списка тарифов. После изменения снимка новая вкладка сохраняет исходные API-строки, но не допускает подписки до повторной проверки аудита. Обычные графики исходного метода остаются доступны.

## Что означает оценка

- Это сценарный перенос расходов API на подписку по выбранному коэффициенту. Проект не запускает тесты через подписки.
- Real API Pricing оценивает цену при использовании доступной месячной квоты. Для прямых квот цена пересчитывается из месячной платы и числа токенов без округления промежуточного результата.
- Для смешанной API-цены используется соглашение Real API Pricing: 97,5% cache read, 2,15% обычного input и 0,35% output. Это не утверждение о составе нагрузки AA; cache write в этой смеси отдельно не моделируется.
- Этот стандарт не означает одинаковую нагрузку всех подписок RAP. У Step денежные квоты пересчитываются по 85% cache / 14,65% input / 0,35% output; прямые измерения общего числа токенов сохраняются без повторной нормализации. Наши API-базы используют стандартный профиль, а эффективные цены подписок сохраняют метод исходного источника.
- Если готовой API-цены нет в Real API Pricing, подтверждённые ставки из AA пересчитываются по этой же смеси. Происхождение базовой цены сохраняется в данных.
- Один коэффициент тарифа применяется ко всем опубликованным effort соответствующей модели. Доступность каждого effort в конкретном продукте и фактический расход его квоты этим не подтверждаются.
- «Задач на $100» — нормировка эффективности. Она не означает возможность купить часть месячной подписки за $100 и не является числом успешно решённых задач.
- При смене тарифа Intelligence Index наследуется из AA. Сравнения не измеряют влияние оболочки продукта, инструментов или иных ограничений подписки.
- Неизвестные значения остаются пустыми. Бесплатная или безлимитная акция не превращается в бесконечное число задач.

## Запуск

Нужен Node.js. Для сборки и проверок нет внешних npm-зависимостей.

```powershell
npm test
npm run build
Start-Process .\output\report.html
```

Для просмотра внутри приложения можно запустить `npm run preview` и открыть `http://127.0.0.1:8765`. Сервер слушает только локальный адрес.

Сборка читает сохранённые данные и не обращается к сети. Получение нового снимка выполняется отдельными скриптами в `scripts/`; сетевой сбой не должен молча подменять снимок неполными данными.

Чтобы обновить оба источника, нужны Python 3 и `curl.exe`:

```powershell
node scripts/fetch_aa.mjs --refresh
python scripts/fetch_pricing.py --refresh
npm test
npm run build
```

Без `--refresh` оба скрипта повторяют нормализацию сохранённых снимков. Если сайт меняет схему или названия моделей, нужно проверить сопоставления и раздел покрытия до использования результата.

На текущем снимке найдены 13 моделей, 42 варианта AA и 62 тарифа подписки. У Grok 4.7 и MiMo V2.6 Pro в RAP нет подписок. AA не публикует цены Sol non-reasoning, Gemini 3.8 Flash low и MiMo V2.5 Pro non-reasoning; их строки сохранены с пустыми ценами.

## Файлы

- `data/aa/aa.json` — варианты моделей AA, стоимости, индекс, источники и признаки оценочных значений.
- `data/aa/task-weighting.json` — проверенные веса тестов и денежные вклады Opus/Fable. После смены снимка AA проверка обновляется отдельно; несовпадающая по дате или версии проверка не включается в отчёт.
- `data/pricing/pricing.json` — тарифы, квоты, эффективные и базовые API-цены.
- `data/*/` — сохранённые исходные материалы для проверки происхождения данных.
- `scripts/calculate.mjs` — формулы и обработка отсутствующих значений.
- `scripts/estimate_api_price.mjs` — обратный расчёт токенов, средние API-цены и проверки по счётчикам AA.
- `scripts/token_scenario.mjs` — отбор наблюдённых квот и независимый расчёт задач по токенам AA.
- `data/pricing/quota-evidence.json` — проверка происхождения каждой квоты, привязанная к снимку тарифов.
- `scripts/build_report.mjs` — точное объединение моделей и сборка отчёта.
- `templates/report.html` — самостоятельный интерфейс отчёта.
- `tests/` — проверки расчётов и целостности объединения.
- `output/` — сгенерированный отчёт и таблицы, не предназначенные для Git.
- `output/api-price-estimates.json` и `.csv` — новые оценки по моделям и effort, ставки, объёмы токенов и результаты сверок.
- `output/token-scenario.json` и `.csv` — условные оценки по наблюдённой ёмкости, источники квот и статусы переноса.
